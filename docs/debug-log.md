# 调试记录

按时间顺序记录开发中遇到的问题。每条只写四行：现象、原因、怎么改、改完怎么验证。
不要事后补写，遇到一个就记一个。

---

## 1. 运行 contacts.exe 后中文全部乱码

- 现象：双击或在 PowerShell 中运行程序，菜单里的中文（通讯录、姓名、地址等）显示为一串乱码字符
- 原因：源文件 main.c 是 UTF-8 编码，但 Windows 控制台默认用 GBK（代码页 936）来解码输出，编码不匹配
- 解决：在 main() 开头加两行 `SetConsoleOutputCP(65001); SetConsoleCP(65001);`，把控制台输入输出都切到 UTF-8
- 验证：重新 `gcc` 编译后运行，中文全部正常显示；双击 exe 也不乱码

## 2. 保存后重新打开，地址后面多出一个空行

- 现象：添加联系人 → 保存 → 退出 → 重新运行 → 显示全部，每条记录的"地址"后面都多了一个空行；用查找功能打印地址时也是如此
- 原因：`load_contacts` 用 `fgets` 读入每一行时，行末的换行符 `\n` 也被读进了 `line`。地址是最后一个字段，直接用 `strncpy` 拷贝时把 `\n` 一起带进了 `contacts[].addr`，打印时就多出一行
- 解决：在 `fgets` 之后、拆分字段之前，判断 `line` 末尾是否为 `\n`，是的话替换成 `\0`（和 `read_line` 里的处理一致）
- 验证：重新编译后，添加 → 保存 → 退出 → 重开 → 显示，地址后面不再有空行；查找时地址也只占一行

## 3. 姓名输入超长时，多出的字符串到了电话和地址字段

- 现象：输入一个 26 个字符的姓名后，电话和地址字段没有等待输入，而是直接被姓名多出来的字符填满了，显示时姓名被截断、电话变成了剩余字符
- 原因：`fgets(buf, size, stdin)` 最多读 `size-1` 个字符；如果输入比这长，它读满就返回，**剩下的字符还留在 stdin 缓冲区里**。下一次调用 `read_line` 时直接读到了这些残留字符，相当于"自动输入"了
- 解决：在 `read_line` 里判断 `fgets` 读到的末尾是否为 `\n`；如果不是，说明输入超长，用 `while (getchar() != '\n')` 把缓冲区里的残留字符清空
- 验证：重新编译后输入 26 字符姓名，姓名被截断到 20，电话字段正常等待输入，不再串字段；程序也不会因为超长输入崩溃
